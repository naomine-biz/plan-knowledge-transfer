# PR #4：初心者モードの修正候補

初心者モードの考え方を引き継ぎ、現行mainの「知識移転計画を完成させる」スキルへ組み込むための変更を整理する。Lv0からLv1、Lv2への接続は、目標がLv5/Lv6の場合にも使う案として検討する。実装前の候補である。

比較対象は、PR #4の`moomindani/plan-knowledge-transfer:beginner-mode`（`7c434a9`）と、main（`09809ca`）。共通祖先は`f99f5fe`で、PRは計画専用への改訂前の構成を使っている。確認した主要7ファイルは、ローカルの`69d8cf6`とmainで同一だった。

## 引き継ぐ考え方

- 通常モードの到達目標はLv5またはLv6とし、Lv2以上の理解を積み上げる設計を引き継ぐ。
- 初心者モードは、Lv0の体験から、Lv1の「考える必要への気づき」、必要に応じてLv2の「原因と結果をつなぐ筋道」へ進む。
- 初心者指定、Lv1/Lv2の目標指定、用語や操作をまだ知らない読者など、元PRの選択条件を出発点にする。
- Lv1では、同じやり方でうまくいく場合とうまくいかない場合の違いから、考えるべき点に気づく。
- 長い文書では、まとまりごとの目標をLv1からLv2へ引き上げられる。新しい主題のLv0の体験と、前のまとまりから引き継ぐ気づき・筋道の関係を計画する。
- 準備や最初の体験に集中するまとまりはLv0で終えられる。その後のどこでLv1へ進むかを対応させる。

7段階の短い定義と参照概念は、現行mainのまま使う。Lv0からの接続は、読者の能力の評価ではなく、計画の入口を構造化する設定として記述する。

## 目標にかかわらずLv0からの接続を試す

到達目標と、読者が説明へ入る起点を分ける。通常モードでも、読者が普段は理由を検討せずに使っている手順や経験をLv0の起点として、Lv1の気づきとLv2の論理へ接続する案を試す。

| 段階 | 共通の入口として計画するもの |
|---|---|
| Lv0 | 読者がそのまま使っている手順、経験した結果。読者にまだない場合は、導入に必要な体験・結果。 |
| Lv1 | そのやり方や結果の違いから、何を考える必要があると気づくか。 |
| Lv2 | 気づいた点について追う論理と、その前提・因果関係。 |

Lv5/Lv6を目標にする場合も、この入口から必要な理解へ進む経路を計画する。Lv1が目標なら、Lv1までの到達で止める。

Lv0の起点が既に読者にある場合は、既知の前提として記録し、どの気づきに使うかを対応させる。新しい操作体験の実施や、Lv0専用の章を一律に要求する形にはしない。起点が不明な場合は仮定として扱い、読者ペルソナの条件と照合する。

この接続によって、Lv2の論理が何を考えるために必要なのかを、計画で特定しやすくなるかを確認する。現時点では、生成結果で有効性を確かめていない。

## 知識の出発点と、必要な思考を対応させる

元PRは、前提知識がない読者に、知識と考えるきっかけをどこから与えるかという論点も示している。現行スキルで扱っている読者の前提知識と理解の項目の対応を、Lv0/Lv1を含む入口の設計へ広げる。

知識量は、そのテーマについて何を既知として使え、何を新しく獲得する必要があるかに具体化して扱う。その知識を使って、どの比較・推論・点検・判断へ進むかを思考の段階と対応させる。

| 計画すること | 記録する内容 |
|---|---|
| 読者が既に持つ知識 | 対象の用語・概念・操作・経験した結果・関係・条件のうち、既知として使えるもの。 |
| 新しく獲得する知識 | 到達目標に必要で、まだ既知として使えない事実・概念・関係・条件。 |
| 知識を使う思考 | その知識から何に気づき、どの論理を追い、どの条件や根拠を点検し、何を判断するか。 |

Lv0の体験は、後の気づきや論理で使う結果・手順などを得る入口として計画できる。既にその知識や経験があれば前提として使い、不足する部分は導入で得るものとして定める。Lv1以降も、各段階に必要な知識を前の項目や既知の内容へ対応させる。

これらは既存の「達成する理解」「必要とする理解」と段階との対応に記録する。知識量の数値化や、読者の思考力全般の採点を新しい作業に加えない。

点検では、必要な知識が欠けている箇所と、その知識から結論へ進むつながりが欠けている箇所を区別する。知識の不足には必要な内容を追加し、つながりの不足には関係の分解や順序の修正を行う。

直近の議論では、知識がないためにそのテーマの思考がまだ始まっていない状態を、Lv0の出発点として扱う捉え方も検討している。知識がなくても「調べて考える必要がある」と気づいている状態は、Lv1として扱える。知識の不足をLv0になる理由の一つとし、知識量と段階を固定的に対応させる定義にはしない。

この捉え方と、既知の手順を理由の検討なしに使うLv0の起点を、計画にどう表すかは未決である。いずれも、そのテーマについての計画の設定として検討し、読者の思考力全般の評価には使わない。

## 計画専用の構成へ置き換える内容

### 到達点を「本文」から「読者の到達目標」へ変える

元PRの「Lv1/Lv2の説明を先に作る」は、目標を先に定めて必要な内容を逆算する考え方として引き継ぐ。成果物には読者向けの説明文を作らず、どの点に気づき、どの関係を理解するかを書く。

| 段階 | 初心者計画で定めるもの |
|---|---|
| Lv0 | 後の気づきの前提になる体験・結果。詳しい操作手順、画面、本文は作らない。 |
| Lv1 | どの条件・結果の違いから、何を考える必要があると気づくか。 |
| Lv2 | その点について理解する原因と結果の関係と、手順や判断を組み立てる理由。 |

成功・失敗の対比は残し、計画には比較する条件、結果の違い、気づく対象を記録する。具体的な例の筋書きを作る工程にはしない。

### Lv0とLv1を現行の計画項目へ対応させる

現行の理解の項目は、因果・関係・成立条件などを具体化する形式である。初心者モードでは、Lv1の「どこを考える必要があるか」という気づきも、目的に必要な到達状態として表せるようにする。

Lv0の項目は準備となる体験・結果を記録し、後でそれを使うLv1の項目へつなぐ。Lv0の準備だけで計画全体が完成したとは扱わない。まとまりがLv0で終わる場合も、後の到達目標への接続を点検する。

項目の階層と、Lv0/Lv1/Lv2の段階は別に記録する。まとまりや段階を、固定の章数・段落数・項目数へ置き換えない。

### 長い文書の進み方を計画で表す

元PRの、前半から後半へ目標を引き上げる方法と、新しい主題の体験から始める方法を残す。単位ごとに、開始点、到達目標、前の単位から引き継ぐ前提、次へ渡す気づき・理解を対応させる。

単位は意味のある理解のまとまりとして扱い、具体的な章・節の割り付けを計画の完成条件にしない。前の単位で得た気づきや筋道が、後の単位のどの項目を支えるかを確認する。

### 書き方の助言を、理解と前提の点検へ変える

| 元PRの助言 | 計画で扱う内容 |
|---|---|
| 用語を使う前にやさしく言い換える | 初めて使う概念に、必要な意味と前提の理解を対応させる。 |
| 一つのまとまりで気づかせることを一つにする | 一つの気づきの対象を特定できる粒度に分解し、必要な気づきの間をつなぐ。 |
| 体験を先に、理屈を後に置く | 体験・結果から気づきへ、気づきから筋道へ進む前提関係を記録する。 |
| 失敗を読者の責任にしない | 結果の違いを、読者個人の評価ではなく対象の条件へ対応させる。 |
| 手元の結果と本文の違いを説明する | 環境・条件によって変わる結果と、気づきに必要な違いを区別する。 |
| 操作手順・画面・結果を確かめる | 到達目標を支える事実・結果について確認した範囲と未確認事項を記録する。具体的な操作手順や画面の制作・点検は計画の作業範囲に加えない。 |

### 気づきに使う結果の違いを確かめる

元PRの「読者の手元で起きない失敗を教材の前提にしない」という考え方は残す。仕様・版・環境・成立条件によって結果が変わる場合は、その条件と根拠を計画に記録する。道具の更新で消えやすい差より、成立条件を説明できる差を優先する。

「仕組みのうえで必ず起きる」は、どの条件でその結果が生じるかを確認する表現へ変える。確認方法と要否は現行mainの事実確認の手順に従い、資料で確認したことと実機で再現したことを区別する。実機再現をすべての計画の完成条件にはしない。

初心者の到達目標をLv1/Lv2に限定しても、計画担当が必要な条件や根拠を確認する工程は共通で行う。読者にLv3以上の理解を要求しないことと、計画担当による検証を省くことを分ける。

## モード選択と点検の修正候補

元PRの初心者向けの選択条件を維持したうえで、ユーザーが指定した目的・到達目標との優先順位を明確にする。

| 依頼の条件 | 選択候補 |
|---|---|
| 初心者モード、またはLv1/Lv2を指定 | 初心者モードを使う。 |
| 用語や操作をまだ知らず、体験から気づき・筋道へ進む入門が目的 | 初心者モードを使う。 |
| テーマの前提知識は不足するが、Lv5/Lv6やシステム理解・戦略的判断が目的として指定されている | 指定された到達目標を保ち、Lv0からの入口と必要な前提を計画する。 |
| 目的・目標や混在する読者条件から選択できない | 現行の目標確認を使い、モードと到達目標を確認する。 |

前提知識だけで上位の目的を上書きせず、初心者モードを選べる入口は残す。この優先順位は修正案の方針として確認する対象である。

読者ペルソナの点検では、Lv1の目標に対して、気づく対象とその根拠になる違いを追えるかを確認する。Lv2では、原因と結果を追い、手順や判断の理由へつなげられるかを確認する。目標より上の理解を答えられないことだけで、不足と判定しない。

## 修正候補を確かめるケース

実装後は次のケースで、モード選択、到達目標、前提のつながり、成果物の範囲を確認する。以下は確認予定であり、生成結果による検証はまだ行っていない。

| ケース | 確認する結果 |
|---|---|
| Lv1を目標にした初めての題材 | 体験・結果と、気づくべき点がつながる。因果の説明やシステム理解を追加の完成条件にしない。 |
| Lv2を目標にした初めての題材 | 体験から気づき、気づきから原因と結果へ進み、手順・判断の理由までつながる。 |
| Lv0の準備、Lv1の前半、Lv2の後半を持つ長い文書 | 目標を引き上げる単位と、引き継ぐ気づき・理解を特定できる。Lv0だけの準備にも後の項目への接続がある。 |
| 前提知識が少ない読者にLv5/Lv6を指定 | 指定された目標を保ち、不足する前提を理解の項目として補う。 |
| 既知の手順・経験がある読者にLv5/Lv6を指定 | 既知の起点から、気づきと論理を経て到達目標へつながる。新しい操作体験を一律に追加しない。 |
| 同じ到達目標で、読者の既知の知識を変える | 新しく獲得する知識と必要な前提が読者条件に応じて変わり、各段階で使う知識への経路がつながる。 |
| 用語や操作は知っているが、その理由や条件を既知としていない読者 | 既知の内容を起点に、気づきと因果・条件の理解へ接続する。用語や操作を知っていることだけで、関係や条件の理解も既知と仮定しない。 |
| 既存サンプル相当のLv5とLv6の依頼 | Lv0からの入口を加えた計画と従来の計画を比較する。目標への寄与、前提のつながり、余分な説明項目の有無を点検し、通常モードの完成条件と作業範囲を保つ。 |
| 未知の題材、または版・環境に依存する結果の違い | 題材理解の確認や必要な事実確認が働き、未確認の結果を再現済みと扱わない。 |

Lv1/Lv2の代表的な計画と点検記録を、実装後の候補に添える。既存サンプルの`prompt.md`は記事執筆用なので、通常モードの確認には計画に記録された目的・読者条件から計画作成の依頼を用意する。記事の生成は今回の確認の完成条件にしない。

修正候補の実装は現在のmainを起点に、初心者モードの変更を移植して作る。元PRの旧版ファイルをまとめて採用する方法にはせず、現行の計画専用の手順・出典整理・サンプルを保つ。元PRを引き継いだことは、候補のPR説明でPR #4への参照として残す。
