# 知識移転の根本思想

## モデルの出典と位置づけ

このスキルの7段階は、深淵回廊の動画を参考に、技術的な知識移転の設計用に整理したものである。

- 直接参考にした資料：深淵回廊「[【思考心理学】本当に頭が良い人は何を考えているのか?](https://www.youtube.com/watch?v=4cCFqBsXZ2E)」（YouTube）
- 提案者による補足説明：深淵回廊「[【思考心理学】思考力の7段階〜完全版〜](https://note.com/shinen_kairo/n/nb7db02119df5)」（note）

動画の説明欄では、7段階の枠組みを心理学・認知科学の概念を段階状に整理したモデルと説明し、単一の学術的尺度ではないとしている。
補足記事でも、7段階という整理は著者独自のモデルであり、学術的に検証された単一の尺度ではないと明記されている。

本スキルでは、段階番号を動画のLevel1〜Level7からLv0〜Lv6へ変更し、定義の表現を説明設計の用途に合わせて整理している。
Lv2から目標まで説明を組み立てる手順、Lv4で実例・実データにより前提を点検する方法、Lv5のシステム理解またはLv6の組織の戦略的判断を到達目標とする方針は、本スキルで具体化したものである。

## 思考の7段階

このスキルでは、物事を説明する際の思考を次の7段階として扱う。
対象概念を理解し、説明を設計するための段階である。

| 段階 | 定義 |
|---|---|
| Lv0 | 思考しない |
| Lv1 | 思考が必要であることに気づく |
| Lv2 | 論理的思考 |
| Lv3 | 批判的思考 |
| Lv4 | 自身のバイアスを認識している |
| Lv5 | 概念のシステム（構造）を認識している |
| Lv6 | 戦略的である |

技術的説明の目的は、あるテーマについて、読者がLv5またはLv6の思考レベルで理解に到達することである。
書き手は目標レベルの説明を先に作り、それを理解するための説明をLv2から順に組み立てる。

Lv0とLv1はこのモデルの定義に含める。技術的な概念説明の出発点はLv2に置く。
この段階を読者の人格や能力全般の評価として使わない。

## 1. 読者と到達目標を定める

テーマ、対象読者、文書が答える問いを確認し、到達目標をLv5かLv6に定める。
ユーザーがどちらかを指定している場合は、その指定を優先する。

| 対象読者 | 到達目標 |
|---|---|
| 上位の技術職。技術リーダー、アーキテクトなど | Lv5 |
| 組織の意思決定を担う立場。CxO、部門長など | Lv6 |

読者の役割が不明、複数の役割が混在するなど、目標を決められない場合はHumanに問い合わせる。
Lv5のシステム理解とLv6の戦略的判断のどちらを目指すかを確認し、回答を得てから目標レベルの説明を作る。

## 2. 目標レベルの説明を先に作る

書き手がテーマを目標レベルで捉え、依頼者が確認できる説明文として先に作成・提示する。
その文章を、読者向け本文の到達点にする。

- **Lv5の説明**：全体で実現したい系（システム）から説明する。全体の目的、要素間の関係、対象技術の役割、状態や情報の流れ、成立条件を結び付け、どういうシステムが実現されるかを示す。
- **Lv6の説明**：Lv5のシステム理解を踏まえ、組織の目的や制約に対する選択、優先順位、投資や資源の配分、実行方針、判断を見直す条件を説明する。

たとえば分散トランザクションのLv5説明では、アプリケーション全体で実現したいシステムを先に描き、各処理や保存状態の関係をそろえるうえで、この技術が担う役割を説明する。
部品の一覧や構造図だけで終えず、全体として実現される動作と条件を文章にする。

必要な関係や根拠が不明な場合は、資料を確認する。
不明な部分を想像で埋めて、目標レベルの説明ができたことにしない。

## 3. 到達点から必要な説明を洗い出す

目標レベルの説明に含まれる主張ごとに、読者が必要とする前提知識、論理のつながり、反例、実証の材料を整理する。
章、節、短い解説など、その依頼で意味を持つまとまりで設計し、次の順序で本文を組み立てる。

| 段階 | 本文で説明すること | 読者の到達状態 |
|---|---|---|
| Lv2 論理をつなぐ | システム全体の論理のつながりを、定義、入力、処理、状態の変化、結果に分けて一ステップずつ説明する。 | 全体の動作がどのような論理で成立するかを追える。 |
| Lv3 反例を検証する | Lv2の論理に反する例や、条件を変えると成立しなくなる例を検証する。成立条件と限界を明確にする。 | どの条件で論理が成立し、どこで見直しが必要かを判断できる。 |
| Lv4 実例・実データで実証する | 実際の事例、観測結果、測定データを使い、ここまでの説明が正しいことを、その根拠が支える範囲で示す。説明や事例の選び方に置いた前提も点検する。 | 論理と実証を結び付け、自分の前提や偏り、検証できた範囲を認識できる。 |
| Lv5 実現されるシステムを説明する | 検証した論理と実証を統合し、この技術を使ってどういう系が実現されるかを、全体の目的、要素間の関係、条件から説明する。 | 対象技術によって実現されるシステム全体を理解し、その成立条件を説明できる。 |
| Lv6 戦略的判断へ進む | Lv5のシステムを組織の目的や制約へ結び付け、選択、優先順位、資源の配分、実行方針、見直す条件を説明する。 | 組織としての選択を、理由と実行・見直しの方針とともに示せる。 |

Lv4では、実例や実データに照らして、書き手と読者が当然とした前提や事例選択の偏りを点検できるようにする。
これを「自身のバイアスを認識している」という思考の定義に対応する説明作業とする。
読者のバイアスを決めつけず、採用した事例の条件やデータの取り方を示し、自身の見方を点検する材料を渡す。

実例や実データの出典、条件、測定方法は、[knowledge-transfer-plan.md](knowledge-transfer-plan.md)の材料と未解決事項に記録する。
仮定した場面や架空の数値は、論理を説明する例として扱い、実証の根拠には使わない。
実例が不足する場合は、実証できていない範囲を明示する。限られた事例から、あらゆる条件での正しさを断定しない。
反例や実データが説明と合わない場合は、前の論理や目標レベルの説明を修正し、確かめ直す。

計画が必要な執筆では、洗い出した内容を[knowledge-transfer-plan.md](knowledge-transfer-plan.md)に従って依頼者向けの計画にまとめ、承認後に読者向け本文へ展開する。

## 執筆の判断を本文へ展開する

対象読者、目標レベル、表の「読者の到達状態」は、書き手が説明を設計し、原稿を評価するために使う。
読者が目標の理解に到達できるよう、必要な論理と根拠をそろえ、関係を説明する責任は書き手が負う。
完成稿には、対象技術の動作、成立条件、根拠、それらを組み合わせて実現されるシステムや戦略を書く。

「読者が全体の動作を説明できる」という到達状態は、本文で全体の動作を具体的に説明することで満たす。
問いを使う場合は、その問いへの答えと理由を本文で示す。説明を終える箇所では、確認済みの関係を結び付けて結論を述べる。
対象読者の役職や思考レベルは執筆条件として扱い、本文には理解に必要な前提と技術内容を示す。
読者向けの対象者案内、学習目標、演習を依頼された場合は、その用途に合わせて記載する。

## 一段ずつ導くための構成

- 後の段階で使う概念や根拠を、前の段階で導入する。
- 各段階は、前の段階で得た理解を使って説明する。
- 先に作る目標レベルの説明は、依頼者向けの下書きとして扱う。完成稿の読者向け本文はLv2から始め、目標レベルへ進める。
- 具体的な場面や問いを本文の導入に使ってもよい。
- 高度な用語、構造図、推奨構成だけを提示して段階を飛ばさない。
- 段階名の見出しを付けることを必須にしない。読者向けには対象の問いに合う見出しを使い、内容と順序で段階を満たす。
- すべての段落や図注に各段階を繰り返さない。説明のまとまり全体でLv2から目標レベルまで進める。
- 短い説明でも、必要な段階の根拠とつながりを残す。長さを減らすために上位の結論だけを抜き出さない。
- すでに導入した概念は参照できるようにする。構成を変える推敲では、移動した説明の前提が失われていないか確認する。

誤字修正など論旨を変えない編集で、依頼された範囲を超えて章を増やす必要はない。
説明を作る、組み直す、評価する場合に、この思想を構成とレビューの基準として使う。
