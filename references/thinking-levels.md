# 知識移転の根本思想

## モデルの出典と位置づけ

このスキルの7段階は、深淵回廊の動画を参考に、技術的な知識移転の設計用に整理したものである。

- 直接参考にした資料：深淵回廊「[【思考心理学】本当に頭が良い人は何を考えているのか?](https://www.youtube.com/watch?v=4cCFqBsXZ2E)」（YouTube）
- 提案者による補足説明：深淵回廊「[【思考心理学】思考力の7段階〜完全版〜](https://note.com/shinen_kairo/n/nb7db02119df5)」（note）

動画の説明欄では、7段階の枠組みを心理学・認知科学の概念を段階状に整理したモデルと説明し、単一の学術的尺度ではないとしている。
補足記事でも、7段階という整理は著者独自のモデルであり、学術的に検証された単一の尺度ではないと明記されている。

本スキルでは、段階番号を動画のLevel1〜Level7からLv0〜Lv6へ変更し、定義の表現を説明設計の用途に合わせて整理している。
Lv2から目標まで理解を積み上げる計画、Lv4で実例・実データにより前提を点検する方法、Lv5のシステム理解またはLv6の組織の戦略的判断を到達目標とする方針は、本スキルで具体化したものである。

## 思考の7段階

このスキルでは、思考に次の7段階があると仮定し、知識移転の計画を構造化するために用いる。

| 段階 | 定義 |
|---|---|
| Lv0 | 思考しない |
| Lv1 | 思考が必要であることに気づく |
| Lv2 | 論理的思考 |
| Lv3 | 批判的思考 |
| Lv4 | バイアスを認識している |
| Lv5 | システム（構造）を認識している |
| Lv6 | 戦略的である |

技術的説明の目的は、あるテーマについて、読者がLv5またはLv6の思考レベルで理解に到達することである。
計画担当は対象を目標レベルで捉え、読者の到達目標を先に定める。その目標に必要な理解を洗い出し、Lv2から順に積み上げる計画を作る。

Lv0とLv1はこのモデルの定義に含める。技術的な概念説明の出発点はLv2に置く。
この段階を読者の人格や能力全般の評価として使わない。

## 1. 読者と到達目標を定める

テーマ、対象読者、文書が答える問いを確認し、到達目標をLv5かLv6に定める。
ユーザーがどちらかを指定している場合は、その指定を優先する。

| 対象読者 | 到達目標 |
|---|---|
| 上位の技術職。技術リーダー、アーキテクトなど | Lv5 |
| 組織の意思決定を担う立場。CxO、部門長など | Lv6 |

読者の役割が不明、複数の役割が混在するなど、目標を決められない場合はHumanに問い合わせる。
Lv5のシステム理解とLv6の戦略的判断のどちらを目指すかを確認し、回答を得てから到達目標を定める。

## 2. 目標レベルで対象を捉える

計画担当が世界知識と依頼の文脈からテーマを目標レベルで捉え、全体の関係と成立条件を整理する。
全体像を組み立てられない場合は、[題材のリサーチとHumanによる確認](knowledge-transfer-plan.md#題材の全体像を組み立てられない場合)を先に行う。
計画には、読者が最終的に理解すべき関係・条件・判断を到達目標として示す。

- **Lv5の到達目標**：全体の目的、要素間の関係、対象技術の役割、状態や情報の流れ、成立条件を結び付け、実現される系（システム）を理解する。
- **Lv6の到達目標**：Lv5のシステム理解を踏まえ、組織の目的や制約に対する選択、優先順位、投資や資源の配分、実行方針、判断を見直す条件を理解する。

[世界知識で構造を作り、必要な事実を確認する](knowledge-transfer-plan.md#世界知識で構造を作り必要な事実を確認する)手順に従い、理解の経路を組んでから、必要な関係や根拠の確認対象を選ぶ。
不明な関係を想像で埋めて、到達目標を説明可能と判断しない。

## 3. 到達目標から必要な理解を洗い出す

到達目標を満たすために必要な理解と、その前提・つながりを整理する。
理解の項目の分解方法と粒度は[knowledge-transfer-plan.md](knowledge-transfer-plan.md)に従う。
章、節、短い解説など、その依頼で意味を持つまとまりで設計し、次の段階を使って理解を積み上げる。
下表は各段階で定める理解を示す。計画には、そのテーマ固有の関係・条件・判断を具体化する。

| 段階 | 計画で定める読者の理解 |
|---|---|
| Lv2 論理をつなぐ | 対象を必要とする理由や問題、定義、入力、処理、状態の変化、結果を結び付け、全体の論理を一ステップずつ追える。 |
| Lv3 反例を検証する | 条件を変えると成立しなくなる例や論理に反する例を踏まえ、成立範囲と見直しが必要な条件を判断できる。 |
| Lv4 根拠と前提を点検する | 実例・観測・測定が裏付ける範囲を把握し、採用した前提や事例・データの選び方の偏りを点検できる。 |
| Lv5 システムを捉える | 検証した関係と根拠を統合し、全体の目的、要素間の関係、成立条件から、実現されるシステムを理解できる。 |
| Lv6 戦略的判断へ進む | Lv5の理解を組織の目的と制約へ結び付け、選択、優先順位、資源の配分、実行と見直しを判断できる。 |

Lv4では、実例や実データに照らして、計画担当と読者が当然とした前提や事例選択の偏りを点検する理解を定める。
これを「バイアスを認識している」という思考の定義に対応する計画として扱う。
読者のバイアスを決めつけず、採用した事例の条件やデータの取り方と、点検する前提を計画に記録する。

実例や実データの出典、条件、測定方法は、[knowledge-transfer-plan.md](knowledge-transfer-plan.md)の根拠と未解決事項に記録する。
仮定した場面や架空の数値は、論理を説明する例として扱い、実証の根拠には使わない。
実例が不足する場合は、実証できていない範囲を明示する。限られた事例から、あらゆる条件での正しさを断定しない。
反例や実データが想定した関係と合わない場合は、計画の論理や到達目標の成立条件を修正し、確かめ直す。

必要な理解を[knowledge-transfer-plan.md](knowledge-transfer-plan.md)に従って依頼者向けの計画にまとめる。

## 理解を一段ずつ積み上げる順序

- 後の段階で必要な概念や根拠を、前の段階の理解に対応させる。
- 各段階が、前の段階で得るどの理解を使うかを示す。
- 目標から必要な理解を洗い出し、計画の順序はLv2から目標レベルへ進むように定める。
- 新しい概念には、それを必要とする問題や要求の理解を対応させる。
- 高度な用語や上位の結論を、必要な前提を飛ばす代わりに使わない。
- 詳細を含めるかは、到達目標への寄与から判断する。
- すべての項目に全段階を繰り返さず、意味のある説明単位全体で各段階を満たすよう設計する。
- 短い計画でも、目的に必要な前提、根拠、段階間のつながりを残す。
- 計画を組み直す場合は、移動した項目の前提とつながりを確認する。
