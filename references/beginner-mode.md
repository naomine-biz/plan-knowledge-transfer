# 初心者モードで計画する

考える必要への気づき（Lv1）、または原因と結果をつなぐ理解（Lv2）が目的のときに読む。
モードと到達目標は[thinking-levels.md](thinking-levels.md)、計画の形式と事実確認・承認は[knowledge-transfer-plan.md](knowledge-transfer-plan.md)に従う。

## 到達目標から入口をつなぐ

読者向けの説明文を先に書く代わりに、何に気づき、どの関係を理解するかを到達目標として定め、必要な知識と前提を逆算する。

| 段階 | 計画に記録するもの |
|---|---|
| Lv0 | 後の気づきに使う手順・体験・結果。既知として使うものと、導入で得るものを区別する。 |
| Lv1 | 比較する条件、結果の違い、そこから考える必要に気づく対象。 |
| Lv2 | 気づいた対象について追う原因と結果の関係、手順や判断の理由。 |

同じやり方でも成功・失敗が分かれる条件や、期待と結果の違いを、気づきのきっかけとして使える。単に失敗させることを目的にせず、何の違いから何に気づくかを対応させる。具体的な操作手順、画面、例の筋書きや本文は作らない。

Lv1が目標なら、気づく対象とそのきっかけへの経路がつながったところで止める。因果の説明を追加の完成条件にしない。Lv2が目標なら、そこから原因と結果、手順・判断の理由へ進む。Lv3以上の理解を完成条件に加えない。
用語の意味、事実、体験した結果など、気づきに必要な知識は低い目標でも省かない。

## 準備と複数単位のつながり

準備や最初の体験に集中する単位はLv0で終えられるが、その結果を使う後のLv1の項目へ接続する。計画全体をLv0だけで完成としない。
長い文書では、単位ごとに起点・目標・引き継ぐ前提を定め、前半のLv1の気づきから後半のLv2の理解へ目標を引き上げられる。
新しい主題の入口では、前の単位で得た知識・気づき・論理をどこで再利用するか示す。すべての単位に新たな体験を繰り返させない。

## 気づきに使う違いを確認する

条件や結果の違いが読者の版・環境・前提で成立するか、共通の事実確認の手順に従って確認する。
道具の更新で消える失敗を無条件の前提にせず、差が生じる条件と根拠を記録する。結果の違いを読者個人の能力や責任へ結び付けない。
資料で確認したこと、実機で再現したこと、仮定・未確認事項を区別する。すべての計画に実機再現を要求しないが、確認できない違いが到達目標を支えるなら、その不足を解消するか、条件と入口を修正する。

計画担当による条件・根拠の確認と、読者に求める到達レベルは別に扱う。点検には[reader-review.md](reader-review.md)を使い、知識の不足と、知識から気づき・結論へ進むつながりの不足を見分ける。
