# 知識移転計画の完成条件を確認する

[thinking-levels.md](thinking-levels.md)に基づき、執筆目的を満たす理解の項目とつながりを確認する。
起点から選んだ到達レベルまでの接続を点検し、到達レベルより上の段階がないことを不足としない。

## 入力と到達目標

- [ ] テーマ、執筆目的、想定読者の前提知識、文書が答える問いと範囲が定まっている。
- [ ] 複数の独立したテーマを扱う場合は、計画の単位と、共通の条件・単位間の前提が定まっている。
- [ ] 通常モードのLv5/Lv6または初心者モードのLv1/Lv2に目標が定まり、目的やユーザーの指定に対応している。前提知識の不足だけで指定された上位の目標を下げていない。不明だった場合はHumanに確認している。
- [ ] 題材の全体像を組み立てられなかった場合は、資料で調べた題材理解をHumanに確認してから、到達目標の設定と理解の分解へ進んでいる。確認の引き継ぎや明示的な省略は記録している。
- [ ] 計画担当が目標レベルで対象を捉え、読者が最終的に気づく対象、または理解すべき具体的な関係・条件・判断を到達目標にしている。

## 理解の粒度と執筆目的の充足

- [ ] 各項目が、読者に達成してもらう理解を表している。見出し、図表の仕様、例の筋書き、文章量の指定に置き換わっていない。
- [ ] 各項目で、体験・結果、気づく対象、または理解すべき因果、関係、条件、区別や判断が特定できる。作業名だけで終わっていない。
- [ ] 子項目の理解が親項目につながり、複数の関係を一つの曖昧な項目にまとめていない。
- [ ] 執筆目的と文書が答える問いの各要素が、到達目標と理解の項目に対応している。
- [ ] 到達目標に必要な前提を、読者の既知の内容または計画の項目で支えている。
- [ ] 既知の知識と新しく得る知識を、それを使う思考へ対応させている。用語・操作の既知から理由や条件の理解も既知と仮定していない。
- [ ] 各項目が到達目標を支え、関連するだけの話題や重複する要求を整理している。
- [ ] 目的の充足を、対象分野の網羅性、項目数、文章量で判断していない。
- [ ] 理解の対象と前提・つながりを特定できる粒度に達し、分解を止める理由が目的と読者の条件に対応している。

## 読者ペルソナによる点検

- [ ] [reader-review.md](reader-review.md)に従い、目標レベル、読者の役割、対象テーマの既知の内容とこれから獲得する理解を設定している。
- [ ] 理解への経路と問いに対応する項目、途中で必要な前提を確認している。
- [ ] 知識の不足と、その知識から気づきや結論へ進むつながりの不足を区別している。
- [ ] 読者役の自己申告に加えて、計画・根拠との対応を照合し、目的に必要な不足を修正している。
- [ ] 追加質問の採否を目的から判断し、分解を止める理由、残る不足、実行した文脈を記録している。
- [ ] 仮想の読者による点検を、実際の読者の理解の実証やHumanの承認と区別している。

## 各段階の役割とつながり

- [ ] 理解の項目と起点から目標までの段階が対応している。既に得ている気づきや論理は前提として使い、再体験や全段階の繰り返しを一律に課していない。項目の階層や粒度の例を、思考段階の固定の型として扱っていない。
- [ ] Lv0の起点とLv1の気づき、必要に応じてLv2への接続がある。Lv0の準備だけの単位も後の気づきにつながっている。
- [ ] Lv1では、比較する条件・結果の違いと気づく対象が特定され、Lv1の目標に因果説明を追加の完成条件として課していない。
- [ ] 初心者の気づく対象が、読者の実際の作業・結果・困りごとに対応している。未経験の対象には導入で得る体験・結果がつながり、利用場面の仮定は記録されている。
- [ ] 複数単位では、各単位の起点・目標と、引き継ぐ気づき・理解が対応している。
- [ ] Lv2以上を目指す場合は、Lv2で、対象を必要とする理由や問題と全体の論理を、一ステップずつ追い、その筋道から手順や判断を組み立てるための条件と理由を設計している。
- [ ] Lv3以上を目指す場合は、Lv3で、条件を変えたときの成立範囲や、論理を見直す必要のある条件を判断する理解を設計している。
- [ ] Lv4以上を目指す場合は、Lv4で、根拠が支える範囲と、事例・データの選び方に置いた前提や偏りを点検する理解を設計している。
- [ ] Lv5以上を目指す場合は、Lv5で、全体の目的、要素間の関係、成立条件を結び付け、実現されるシステムを捉える理解を設計している。
- [ ] Lv6を目指す場合は、システム理解を組織の目的と制約へ結び付け、選択、資源の配分、実行と見直しを判断する理解を設計している。
- [ ] 後で必要な概念に、前の段階の理解から進める。上位の用語や結論へ飛躍していない。
- [ ] 導入の理由と、詳しい内部構造や制御手順を理解するための前提がそろっている。
- [ ] 条件の違い、類似する対象、全体の系などを、その理解が目的に必要な場合に含めている。
- [ ] 反例や実データに合わない論理は、計画の理解の項目や到達目標の成立条件へ戻って修正している。

## 根拠と計画の完成条件

- [ ] 世界知識と依頼の文脈から理解の構造を作り、前提の抜け・曖昧さ・飛躍を具体化している。資料収集を一律の出発条件にしていない。
- [ ] 確認対象を、誤りが到達目標・論理・成立範囲・判断へ与える影響から選び、関連する項目と確認する問いを示している。
- [ ] 世界知識からの整理・推論、与えられた前提、資料で確認した事実、未確認事項を区別し、実施していない原典確認や実証を主張していない。
- [ ] 理解の項目と出典、事例・測定の条件が対応し、仮定した例と実証を区別している。
- [ ] 気づきに使う結果の違いが読者の条件で成立するかを確認し、資料で確認したことと実機で再現したことを区別している。低い到達目標でも計画担当による条件・根拠の確認を行っている。
- [ ] 不確かな点、実証できていない範囲、到達目標への影響を示している。必要な根拠や前提の不足を残したまま、完成した計画として扱っていない。
- [ ] このモデルを読者の人格や能力全般の評価として使っていない。
- [ ] 本文や図表の案、原稿のレビュー・校正、制作工程の設計が、計画の作業や成果物に含まれていない。

## 提示と承認状態

- [ ] 短い承認用の要約から、目的、到達目標、理解の順序、範囲、確認状況、依頼者の判断が必要な未解決事項が分かる。
- [ ] 要約と詳細の方針が一致し、計画担当が根拠と計画の充足を点検している。
- [ ] [knowledge-transfer-plan.md](knowledge-transfer-plan.md)に従い、承認待ち・修正中・承認済み、または明示的な承認省略を記録している。
- [ ] 題材理解の確認を行った場合は、完成した計画の承認と別に記録している。Humanの確認を、事実の裏付けとして扱っていない。
- [ ] 計画の完成条件の確認と承認状態を区別し、計画を成果物としてタスクを終了している。
