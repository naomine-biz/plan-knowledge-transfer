# 知識移転の計画と説明構成を確認する

依頼された計画または説明を、[thinking-levels.md](thinking-levels.md)に基づいて確認する。
計画の確認では、各段階で説明する具体的な内容と材料を評価する。本文の確認では、それを説明した箇所を挙げる。
Lv2から選んだ到達レベルまでを適用し、到達レベルより上の段階がないことを不足としない。
初心者向けモードでは、Lv0から選んだ到達レベルまでを適用し、末尾の初心者向けモードの項目も確認する。

## 入力と到達点

- [ ] テーマ、想定読者の前提知識、説明が答える問いと範囲が定まっている。
- [ ] 目標がLv5かLv6に定まり、読者の役割やユーザーの指定に対応している。不明だった場合はHumanに確認している。初心者向けモードでは、末尾の項目で目標を確認する。
- [ ] 書き手が目標レベルの説明そのものを先に作り、依頼者へ提示している。
- [ ] 計画が必要な執筆では、[knowledge-transfer-plan.md](knowledge-transfer-plan.md)に従い、Humanの承認を得てから本文の執筆へ進んでいる。

## 各段階の内容とつながり

- [ ] 到達点の主張に必要な前提、論理、反例、実証の材料が、説明する箇所に対応している。
- [ ] Lv2で、全体の論理を、読者の前提知識に合う言葉で一ステップずつつなぐ。
- [ ] Lv3で、Lv2の論理に反する例や成立しなくなる条件を検証する。
- [ ] Lv4で、実例や実データにより裏付けられる範囲を示し、前提や事例・データの選び方の偏りを点検する材料がある。
- [ ] Lv5で、検証した論理と実証を統合し、全体の目的、要素間の関係、成立条件から、実現されるシステムを説明する。
- [ ] Lv6で、Lv5のシステム理解を組織の目的と制約へ結び付け、選択、優先順位、資源の配分、実行と見直しの方針を説明する。
- [ ] 後で必要な概念を前の段階で導入し、上位の用語や結論へ飛躍していない。
- [ ] 段階名や作業名だけで済ませず、そのテーマで扱う関係、例、根拠を具体化している。
- [ ] 反例や実データに合わない論理を、前の説明や到達点へ戻って修正している。

## 根拠と説明の責任

- [ ] 主張と出典、事例・測定の条件が対応し、仮定した例と実証を区別している。
- [ ] 不確かな点と実証できていない範囲を示し、根拠を超える結論へ広げていない。
- [ ] [執筆の判断を本文へ展開する](thinking-levels.md#執筆の判断を本文へ展開する)に従い、到達状態を満たす説明を具体化している。
- [ ] 本文の確認では、問いに答えと理由があり、終盤で関係を結び付けて全体の動作や判断を説明している。
- [ ] 対象読者や到達状態などの計画事項を本文へ展開し、書き手の説明を読者への課題に置き換えていない。
- [ ] このモデルを読者の人格や能力全般の評価として使っていない。

## 初心者向けモード

[beginner-mode.md](beginner-mode.md)を使う場合に確認する。

- [ ] 目標がLv1かLv2に定まり、まとまりごとに目標を変える場合は、どこから引き上げるかが計画に示されている。
- [ ] Lv0で、理屈より先に、読者が手を動かして結果を得る場面がある。
- [ ] Lv1で、考えずにうまくいく場面と、同じやり方ではうまくいかない場面が対になり、考える必要がある点を言葉にしている。
- [ ] Lv2で、Lv1で気づいた点について、原因と結果を一ステップずつつなぎ、うまくいく手順を組み立て直している。
- [ ] 気づかせたい点が、読者が実際に出会う場面から選ばれている。
- [ ] 1つの説明のまとまりで気づかせることが1つにしぼられ、Lv3以上の内容を先取りしていない。
- [ ] 用語を使う前に言いかえ、説明に不要な用語を出していない。
- [ ] うまくいかない例を、読者の失敗として責める形で書いていない。
- [ ] 操作手順、画面、結果について、確かめた範囲と要確認の点を区別している。
- [ ] Lv0だけで終えるまとまりには、後のどのまとまりでLv1へ進むかが示され、Lv0だけのまとまりが続きすぎていない。
- [ ] 目標を引き上げた後のまとまりも、その主題のLv0から始め、前のまとまりの気づきを筋道の部品として使っている。
- [ ] Lv1のうまくいかない場面が、読者の手元で実際に起きることを確かめている。起きにくい場面は差し替えている。
