# 知識移転の計画と説明構成を確認する

依頼された計画または説明を、[thinking-levels.md](thinking-levels.md)に基づいて確認する。
計画の確認では、執筆目的を満たす理解の項目とつながりを評価する。本文の確認では、それぞれの理解を支える説明を実際にした箇所を挙げる。
Lv2から選んだ到達レベルまでを適用し、到達レベルより上の段階がないことを不足としない。

## 入力と到達目標

- [ ] テーマ、執筆目的、想定読者の前提知識、説明が答える問いと範囲が定まっている。
- [ ] 独立したテーマが並ぶ文書では、章などの説明単位と全体で共通にする条件が定まっている。
- [ ] 目標がLv5かLv6に定まり、読者の役割やユーザーの指定に対応している。不明だった場合はHumanに確認している。
- [ ] 書き手が目標レベルで対象を捉え、読者が最終的に理解すべき具体的な関係・条件・判断を到達目標にしている。
- [ ] 短い承認用の要約から、執筆目的、到達目標、理解の順序、範囲、制作工程、依頼者の判断が必要な未解決事項が分かる。
- [ ] 要約と詳細の方針が一致し、エージェントが根拠と計画の充足を点検している。
- [ ] 計画が必要な執筆では、[knowledge-transfer-plan.md](knowledge-transfer-plan.md)に従い、Humanの承認を得てから本文の執筆へ進んでいる。

## 理解の粒度と執筆目的の充足

- [ ] 各項目が、読者に達成してもらう理解を表している。見出し、図表の仕様、例の筋書き、文章量の指定に置き換わっていない。
- [ ] 各項目で、理解すべき因果、関係、条件、区別や判断が特定できる。「仕組みを説明する」などの作業名だけで終わっていない。
- [ ] 子項目の理解が親項目につながり、複数の関係を一つの曖昧な項目にまとめていない。
- [ ] 執筆目的と文書が答える問いの各要素が、到達目標と理解の項目に対応している。
- [ ] 到達目標に必要な前提を、読者の既知の内容または計画の項目で支えている。
- [ ] 各項目が到達目標を支え、関連するだけの話題や重複する要求を整理している。
- [ ] 目的の充足を、対象分野の網羅性、項目数、文章量で判断していない。
- [ ] 完成稿で理解を支える説明を確かめられる粒度に達し、その先の表現の選択を執筆工程へ渡している。

## 各段階の役割とつながり

- [ ] 理解の項目とLv2から目標までの段階が対応している。項目の階層や粒度の例を、思考段階の固定の型として扱っていない。
- [ ] Lv2で、対象を必要とする理由や問題と全体の論理を、一ステップずつ追える理解を設計している。
- [ ] Lv3で、条件を変えたときの成立範囲や、論理を見直す必要のある条件を判断する理解を設計している。
- [ ] Lv4で、根拠が支える範囲と、事例・データの選び方に置いた前提や偏りを点検する理解を設計している。
- [ ] Lv5で、全体の目的、要素間の関係、成立条件を結び付け、実現されるシステムを捉える理解を設計している。
- [ ] Lv6で、Lv5のシステム理解を組織の目的と制約へ結び付け、選択、資源の配分、実行と見直しを判断する理解を設計している。
- [ ] 後で必要な概念を前の段階で導入し、前の理解を次へつなぐ。上位の用語や結論へ飛躍していない。
- [ ] 導入の理由と、詳しい内部構造や制御手順を理解するための前提がそろっている。
- [ ] 条件の違い、類似する対象、全体の系などを、その理解が目的に必要な場合に含めている。
- [ ] 反例や実データに合わない論理は、前の理解や到達目標の成立条件へ戻って修正している。

## 根拠と説明の責任

- [ ] 理解の項目と出典、事例・測定の条件が対応し、仮定した例と実証を区別している。
- [ ] 不確かな点、実証できていない範囲、到達目標への影響を示している。必要な根拠や前提の不足を残したまま、完成した計画として扱っていない。
- [ ] 本文の確認では、[執筆の判断を本文へ展開する](thinking-levels.md#執筆の判断を本文へ展開する)に従い、各項目に必要な関係や条件を実際に説明した箇所がある。
- [ ] 本文の確認では、用語や項目名の存在だけで充足を判断せず、問いへの答えと理由、全体の動作や判断へのつながりを確かめている。
- [ ] 対象読者や理解の項目は書き手の設計に使い、本文ではその理解を支える説明をしている。説明を読者への課題に置き換えていない。
- [ ] このモデルを読者の人格や能力全般の評価として使っていない。

## 承認後の制作工程

- [ ] 計画に、草稿の執筆、技術説明の推敲、読みやすさの推敲、完成稿の照合の順序と、各工程の入力・作業・完了条件・次へ渡す成果物が記載されている。
- [ ] 具体的な本文、例、図表や配置の選択を執筆工程に置き、各項目の理解を満たすことを完了条件にしている。
- [ ] 推敲で保つ意味・条件・文体と、説明不足を執筆工程で補う扱いが定まっている。
- [ ] 完成稿の確認では、制作工程を実施し、推敲後も各項目の理解を支える説明が特定できる。
